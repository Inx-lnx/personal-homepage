# 崇施涵 · 个人主页

这是一个**纯静态前端项目**，只有 HTML / CSS / JavaScript，无框架、无构建工具、无后端、无依赖。

当前是 **V12**（已发布：<https://Inx-lnx.github.io/personal-homepage/>），视觉为**深空科技风 + 紫青渐变强调**：
全屏深色首屏（打字机进场）、玻璃拟态卡片与 Bento 介绍区、经历时间线 / Now 两个内容区块、
花瓣拼图相册（点击灯箱放大：内联小图 → 过渡图 → 高清图三级渐进）、终端式数字分身（53 条本地知识库）、像素化过渡页脚；字体已本地子集化托管，不依赖 Google Fonts；V10 起带 Service Worker，断网也能打开。
V11 做的是**收敛与可读性**：收掉自动循环的边框灯带、把「灰字流动渐变」的范围缩回首屏标题与姓名两处，移动端首屏改用 `svh`，深色底小字统一提亮到 WCAG AA 之上，并补上「跳到主要内容」与全站 `:focus-visible`。
V12 加了**整站英文版**：顶栏一个按钮切换中英，数字分身换了整套英文知识库，选择记在本地，也能用 `?lang=en` 直接进英文版（见下面「中英文切换」一节）。

## 二选一：怎么在本地打开

### 方式 A：直接双击（最简单）

直接双击 `index.html`，用浏览器打开即可。图片、样式、脚本都是相对路径，离线也能正常显示和提问。

### 方式 B：起一个本地静态服务器（更规范）

在本项目文件夹内打开终端，任选一种：

**用 Python（本机已装）**
```powershell
python -m http.server 8000
```
然后浏览器打开 `http://127.0.0.1:8000/`。按 `Ctrl+C` 可停止服务器。

**用 Node（如果装了 npx）**
```powershell
npx serve .
```

## 发布到公网：让别人输入网址就能访问

线上地址（GitHub Pages，纯静态、免费、带 HTTPS）：

**https://Inx-lnx.github.io/personal-homepage/**

对应的代码仓库：<https://github.com/Inx-lnx/personal-homepage>

### 以后怎么更新线上内容

改完本地文件，在 `personal-homepage` 目录里跑一条命令就行：

```powershell
python tools/deploy_github_pages.py --token-file ..\.deepworks\tmp\github_token.txt --wait
```

脚本 `tools/deploy_github_pages.py` **只用 Python 标准库**，不需要 git / node / npm。
它依次做四件事：确保仓库存在 → 只上传改动过的文件 → 开启 GitHub Pages → 输出访问网址。

### 第一次部署需要准备 token

1. 打开 <https://github.com/settings/tokens/new?scopes=repo&description=personal-homepage-deploy>
2. `Expiration` 选 90 days，勾选 `repo` 权限，点最下方的 **Generate token**
3. 把生成的 `ghp_...` 存进一个文本文件，例如 `..\.deepworks\tmp\github_token.txt`
4. 这个 token 相当于密码，**用完建议去 GitHub 撤销**；下次要更新时再生成一个新的

也可以不落盘，改用环境变量传：

```powershell
$env:GITHUB_TOKEN="ghp_xxx"
python tools/deploy_github_pages.py --wait
```

### 常用参数

| 参数 | 作用 |
| --- | --- |
| `--dry-run` | 只列出会上传哪些文件，不联网、不改动任何东西 |
| `--repo NAME` | 用别的仓库名（默认 `personal-homepage`） |
| `--message "..."` | 自定义提交说明 |
| `--include-all` | 连 `versions/`、`tools/` 一起上传 |
| `--wait` | 部署后轮询等待网址真正可访问再返回 |
| `--workers N` | 并行上传内容的并发数（默认 6） |

### 默认不会上传到公网的内容

- `versions/` —— 旧版本截图与备份，属于本地开发资料
- `tools/` —— 本地工具脚本
- `assets/avatar.png` —— 主站没有引用（页面用的是 `avatar.jpg`），省下约 1.4 MB

### 重新截版本记录图

`versions/vX/` 里的桌面 / 手机整页截图可以用仓库里的脚本重新生成（先让本地预览服务器跑起来）：

```powershell
python tools/capture_screenshots.py --url http://127.0.0.1:8099/ --out-dir versions\v4
```

它会用无头 Edge 固定真实视口（桌面 1440×900 / 手机 390×844）后再抓整页，输出 `screenshot-desktop.png` 与 `screenshot-mobile.png`。
两个坑脚本里已经处理好了：首屏用了 `100vh`（把无头窗口直接设得很高会把整页撑歪、永远截不到底），相册照片是 `loading="lazy"`（不先滚到底触发加载的话，整页图里相册区会是空的）。依赖 `pip install websocket-client`。

### 上线后必须知道的两件事

1. **GitHub Pages 是纯静态托管。** 页面上的 HTML/CSS/JS 和图片都会被浏览器下载下来，
   任何人都能通过开发者工具、抓包或直接下载拿到原始文件。
   `config.js` 里的「内容保护开关」只是威慑，不能真正防住有心人。
2. **只有可公开的密钥才能进前端。** Supabase 的 `publishable key`（旧称 anon key）
   设计上就是公开的，权限由数据库的 RLS 策略控制（见 `supabase/schema.sql`）。
   **绝对不要把 `sb_secret_...` / `service_role` 密钥放进前端或仓库。**

## 字体本地托管 + 子集化（不依赖 Google Fonts）

页面用的是 **Inter**（西文/数字）和 **Noto Sans SC**（中文）。字体文件已经下载到
`assets/fonts/`，由 `assets/fonts/fonts.css` 本地引用 —— **不再访问
fonts.googleapis.com / fonts.gstatic.com**。

这样做的好处：国内网络不用再等 Google，页面不会「先歪一下再变正常」，
访客看到的排版和你本机看到的一致；GitHub Pages 自带 HTTPS，也不会被降级拦截。

### 体积说明

| 项目 | 数值 |
| --- | --- |
| `@font-face` 声明 | 3 条 |
| 实际字体文件 | 3 个 woff2：`inter-subset.woff2` 25.2 KB、`noto-subset-core.woff2` 211.8 KB、`noto-subset-rest.woff2` 40.1 KB |
| 首屏字体总量 | 约 246 KB（fonts.css 8.8 KB + Inter 25.2 KB + 中文首屏 211.8 KB） |
| 延后加载 | noto-subset-rest.woff2 40.1 KB（靠 `unicode-range`，用不到就不下载） |

早期做法是直接搬 Google 的 31 个分块（fonts.css 207 KB + 18 个字体文件，约 1.15 MB），
慢网下光字体就要等 30 秒。V9 起改成**按本站实际用字**生成：扫描 `index.html`、
`404.html`、`assets/*.js`、`assets/*.css` 里出现过的全部字符（当前 1090 个），
拉丁区间交给 Inter，汉字按「首屏常用」和「长尾」拆成两个文件。

Inter 与 Noto Sans SC 都是**可变字体**，同一份文件同时承载 400 / 500 / 600 / 700 / 900
五个字重，所以 3 条声明只对应 3 个文件，渲染结果与旧方案一致。

同一页面、同样限速 50 KB/s 的实测对照：

| 指标 | 旧（Google 分块） | 新（本地子集） |
| --- | --- | --- |
| 字体相关请求 | 20 个 | 4 个 |
| 字体字节 | 1147 KB | 246 KB（-78.5%） |
| 字体落定时间 | 30.1 秒 | 11.7 秒 |

像素级对照：页面总高、8 个区块的位置与高度完全一致，肉眼不可见的抗锯齿像素差 0.058%。

### 以后要更新字体 / 页面新增了生僻字

在项目目录里重新跑一次即可，会自动补齐新用到的子集：

```powershell
python tools/subset_fonts.py --dry-run    # 只看统计，不写文件
python tools/subset_fonts.py --clean-old  # 生成子集，并把旧的 Google 分块归档到 versions/fonts-chunks/
```

两个细节：

- 脚本会把 Inter 的 `opsz`（光学尺寸）轴固定成默认值 —— Google 的分块没有这个轴，
  不固定的话浏览器会对较大字号自动套用光学尺寸，西文字宽会变（实测页脚邮箱链接窄 12px）。
- 源字体缓存在 `tools/.fontcache/`（约 18 MB，`tools/` 不发布，只在本机用）。
  旧的 `tools/localize_fonts.py` 保留作参考，但已被 `tools/subset_fonts.py` 取代。

改完后照常部署：

```powershell
python tools/deploy_github_pages.py --token-file ..\.deepworks\tmp\github_token.txt --wait
```

字体许可：Inter 与 Noto Sans SC 均为 **SIL Open Font License 1.1**，允许自托管与再分发。

## 离线可用（V10 · Service Worker）

站点根目录的 `sw.js` 让页面在断网时也能打开：

- **HTML**：网络优先，离线时回落到缓存里的首页。所以每次联网访问都能拿到最新页面，不会出现「改了却看不到」。
- **静态资源**（CSS / JS / 字体 / 相册图 / 音乐）：缓存优先，第二次访问直接读本地缓存不走网络，同时后台悄悄更新。
- 首页、404 页、样式、脚本、字体 CSS 在首次访问后预缓存；字体二进制与相册图在首次用到时自动入库。
- 首次访问只是把 Service Worker 装上，**第二次打开（或再刷新一次）才由它接管**——这是浏览器规定，不是故障。

### 改了站点文件要顺手做一件事

把 `sw.js` 顶部的版本号加一，例如 `const CACHE = "ph-v13";` → `const CACHE = "ph-v14";`。
不加也能用，但要分清两种情况：HTML 走网络优先，所以页面文字照样是新的；而 `assets/app.js`、`assets/style.css` 这类静态资源走缓存优先，老访客会继续读旧版本。所以**只要改动涉及 CSS 或 JS，这个版本号就必须加**，否则会出现「页面变了、脚本没变」的错位。

### 怎么自己验证离线能不能用

1. 用本地服务器打开页面（见上面「方式 B」），按 F12 打开开发者工具。
2. `Application → Service Workers` 里应看到 `sw.js` 状态为 activated。
3. 在 `Network` 面板勾上 `Offline`，按 Ctrl+R 刷新：页面照常显示，相册、灯箱、数字分身都在。
4. 想清掉缓存：同面板点 `Unregister`，或清一次浏览器缓存。

## 中英文切换（V12）

顶栏那个 `EN / 中文` 按钮就是入口：点一下整站换语言，选择记在 `localStorage` 的 `csh-lang` 里，下次打开还是这个语言。想直接进英文版用 `?lang=en`（按钮切换时也会顺手把这个参数写进地址栏，方便复制给别人）。

语言按这个顺序定：`?lang=` → `localStorage` → 浏览器语言（`navigator.language`）→ 默认中文。`zh-CN` / `en-US` 这类带地区的值会收敛成 `zh` / `en`，其它语言一律回落到中文；因为中文是默认，切回中文时会把地址栏里的 `?lang` 参数删掉。

拆成三个文件：

| 文件 | 干什么 |
| --- | --- |
| `assets/i18n.js` | 文案字典 `window.SITE_I18N = { zh:{…}, en:{…} }`，中英两份 key 同名 |
| `assets/twin-en.js` | 数字分身的英文知识库 `window.TWIN_KB_EN`，与中文表同构、`id` 一一对应 |
| `assets/lang.js` | 语言引擎：检测当前语言、把字典刷到页面、切按钮、写 URL 与 `localStorage` |

### 页面文案怎么跟字典对上

HTML 里不写脚本，只挂属性（`lang.js` 启动时扫一遍，每次切换再扫一遍）：

| 属性 | 作用 |
| --- | --- |
| `data-i18n="key"` | 用字典里的纯文本替换 `textContent` |
| `data-i18n-html="key"` | 用字典里的 HTML 替换 `innerHTML`，值里可以有 `<br>` / `<em>` / `<small>` |
| `data-i18n-attr="placeholder:key;aria-label:key2"` | 按属性名逐个替换 |
| `data-i18n-q="key"` | 替换 `data-q`：快捷提问按钮上显示的字，和实际问出去的那句话可以不一样 |

带箭头的按钮这样写：`<span data-i18n="key">中文</span> <b>↗</b>`——箭头不进字典，字典里只写文字。两种语言写法一样的元素（比如 `SCROLL TO EXPLORE`）不加任何标注。

### 脚本里的文案

`assets/app.js` 顶上备了两个取值工具：`t("key", 中文兜底)` 取字符串，`tList("key", 中文兜底)` 取数组（打字机短语、未命中的推荐问题用这个）。只给脚本用的 key 统一挂 `js.` 前缀，好在字典里一眼分出来。

切换语言时 `lang.js` 会通知所有监听者（`window.I18N.onChange(fn)`，也会派发一次 `site:langchange` 事件），`app.js` 据此重建跟语言绑在一起的东西：换知识库、换欢迎语与兜底答案、重开对话、重刷灯箱读屏标签与背景音乐气泡。已经答过的内容不翻译——那是访客自己问出来的记录，与其留半截旧语言，不如清干净用新语言重来。

### 想加一句翻译

两处都写：`assets/i18n.js` 的 `zh` 与 `en` 各加一行同名 key，再在 HTML 对应元素上挂 `data-i18n`。只写一边不会报错，只是那一处会停在上一次的语言。

### 改英文知识库

跟中文一样在 `assets/twin-en.js` 里改，但有两条硬规矩：`followups` 必须与目标条目的 `ask` **逐字一致**（追问按钮就是拿这串字去提问的）；`keys` 全小写、撇号和空格会被 `normQ` 去掉（所以写 `whats` 而不是 `what's`），另外别用太短的词当命中词，容易误伤别的问法。

## 数字分身怎么改（V4：53 条本地知识库）

### 知识库在哪儿

打开 `assets/app.js`，最顶上的 `TWIN_KB` 就是全部问答内容，一条一个对象：

```js
{ id:"who",                                 // 唯一标识，不要重复
  ask:"你是谁？",                            // 自然问法：输入联想 + 未命中时的推荐问题
  keys:["你是谁","你的名字","自我介绍"],       // 命中词：访客问题里出现任意一个就算命中
  answer:"我叫崇施涵……",                     // 回答文本（邮箱/网址会自动变成可点链接）
  followups:["你在学什么？","怎么联系你？"] }  // 答完推荐接着问的问题，可省略
```

匹配规则：命中的关键词越长、命中数量越多得分越高，得分最高的一条胜出；
一条都没命中时用 `FALLBACK` 回答，并给出几个「肯定答得上」的推荐问题。

### 现在有哪些能力

- 快捷提问按「学习 / 作品 / 兴趣 / 联系」四组展示，点一下就等于提问。
- 回答逐字打字显示；系统开启「减少动态效果」时自动改为整段显示。
- 回答里的邮箱与网址自动变成可点链接。
- 每次回答后附「接着问」按钮，点一下继续追问。
- 输入框打字时向上弹出联想问题：↑↓ 选择、Enter 采用、Esc 关闭。
- 右上角「清空」可以一键重新开始。
- 问不到时不会硬答，而是提示换几个问法。

### 想加一条问答

### 免费项目「闲置 7 天」会被自动暂停（重要）

Supabase 免费套餐的项目**连续 7 天没有活动**就会被自动暂停。暂停后最直观的现象是：
项目域名从 DNS 上消失（`xxxx.supabase.co` 解析不到），页面底部的反馈表单提交失败，
浏览器控制台里会看到 `getaddrinfo failed` 或 `HTTP 521` 之类的报错。
**数据不会丢** —— 到 Supabase 控制台点一下 `Resume project` 就能恢复
（截图里那个白色按钮，别点 `Upgrade to Pro`，那要花钱）。

本站已经用 GitHub Actions 自动保活，正常情况下不会再触发这个问题：

- 工作流文件：`.github/workflows/keep-supabase-alive.yml`
- 频率：每天 02:17 UTC（北京时间 10:17）访问一次项目
- 项目地址和公开密钥**直接读自 `assets/config.js`，工作流里不保存任何密钥**；
  以后换了 Supabase 项目，只要改 `config.js`，保活任务会自动跟着换
- 它同时是「探活」：某天项目完全连不上时，这次运行会**主动失败**，
  GitHub 会给你发邮件提醒 —— 收到邮件就去控制台看看是不是又被暂停了

两个需要知道的限制：

1. GitHub 对 public 仓库的定时任务：**仓库连续 60 天没有提交就会被自动停用**。
   届时到仓库的 `Actions` 页面点一下 `Enable workflow` 即可恢复。
2. 定时任务由 GitHub 调度，可能延迟几分钟到几十分钟，这是正常的。

### 内置曲目（已就绪，开箱可用）

`assets/music/bgm.mp3` 已内置一首**原创纯音乐**（钢琴 + 小提琴）：

| 项目 | 说明 |
| --- | --- |
| 时长 / 大小 | 约 2 分 13 秒 / 2.5 MB / 160 kbps |
| 调性 / 速度 | A 小调 →（B 段）都节调式 / 60 BPM / 4/4 |
| 音色 | **真实采样的钢琴 + 小提琴**（FluidSynth + MuseScore_General.sf3 渲染，见下文「改用真实采样音源」）；早期版本为自研加性合成 |
| 结构 | 前奏 4 小节 → A 段 8 → B 段 8 → A′ 段 8 → 尾奏 4（共 32 小节） |
| 和声 | Am - F - C - G / Am - F - E7 - Am 等小调常用进行 |
| 融合元素 | 挂留和弦（sus2 / sus4）· 钟声式重复动机 · 都节调式 · 物哀留白 · 悠扬长延音 · 弦乐长弓 |
| 版权 | **旋律为原创**，未引用任何既有作品的主题旋律，可安全用于公开页面 |

风格取向是「慢速、怀旧、伤感」的抒情曲（同类曲目的公共音乐语汇），
但旋律与和声编排都是为本项目新写的，不存在版权风险。

本版还融合了一层**东方电影配乐式的色彩**（参考 Merry Christmas, Mr. Lawrence
那类曲目的织体手法）：

- **挂留和弦**：前奏 / B 段 / 尾奏使用 `Asus2`、`Fsus2`、`Csus2`、`Gsus4`，
  有意抽掉三音、只留纯五度 + 大二度叠置 → 空旷、悬置、不落地
- **钟声动机**：A / B / A′ 段用 `A5` / `E5` 交替的钟声动机做八分音符匀速重复，
  像钟声 / 脉搏贯穿全曲；前奏与尾奏留空，形成呼吸感

这里借用的只是**调式、和声色彩与织体手法** ——《圣诞快乐，劳伦斯先生》的
主题旋律受版权保护，本曲**没有使用**它的任何旋律片段。

在此之上，本版又做了**物哀（もののあわれ）向**的整体改造，追求「缥缈虚无」
（下表是乐谱层面的写法；音色与空间处理见下文「音色」一节）：

| 手段 | 具体做法 | 想要的效果 |
| --- | --- | --- |
| 调式 | B 段转入**都节调式**（A - Bb - D - Eb - F） | 自带两个小二度（A↔Bb、D↔Eb），阴翳、无常、无终感 |
| 旋律 | 减到每小节 2~4 个音，长音为主 | 留白本身成为音乐的一部分 |
| 句法 | 句尾小二度 / 级进**下行叹息**，收束回主音 A | 哀而不伤，欲说还休 |
| 伴奏 | 由八分音符改为**四分音符** | 织体疏松，音与音之间腾出空隙 |
| 力度 | 整体压低、段间落差收窄（0.44 ~ 0.66） | 克制优先于张力，不再有情绪的"推上去" |
| 音色 | 起音放缓到 4.5 ms，击槌噪声压得很低 | 音头朦胧，没有锐角 |
| 空间 | 残响抽头 1.3 → 2.0 s，38 ms 预延迟，湿声低通雾化至 2.6~2.85 kHz | 干湿分离 + 高频被吸收 → 声音像隔着一层雾、退到很远 |
| 收尾 | 结尾 3.0 s 渐弱 | 余韵自己散尽，而不是被切断 |

速度也从 66 BPM 降到 60 BPM —— 呼吸更长，句与句之间的空白更从容。
代价是时长从 1 分 59 秒变为 2 分 11 秒。

#### 音色：钢琴（按物理规律做的加性合成）

> **现状说明**：正式曲目**已改用真实采样**（见下文「改用真实采样音源（去掉电子感）」）。
> 这一节描述的是 `tools/make_bgm.py` 的自研合成音色 —— 代码原样保留，
> 作为**不依赖任何外部音源的回退方案**，也可以用来对比「合成 vs 采样」的差异。

音色由 `tools/make_bgm.py` 的 `piano()` 生成，做法仿照真实钢琴的物理规律。
八音盒音色已按需求移除，代码与产物都不再保留（只保留钢琴与小提琴两种）：

| 项目 | 做法 | 听感 |
| --- | --- | --- |
| 泛音频率 | **非谐性拉伸** `f_k = k·f0·√(1+B·k²)`，B 随音高变化 | 不是电子风琴式的整数倍泛音 |
| 泛音衰减 | **逐泛音独立衰减**，高次泛音先死 | 音头亮、尾巴暗 —— 钢琴最标志性的听感 |
| 琴弦 | **三弦**不等幅、不对称微失谐（拍频约 0.3 Hz） | 缓慢的「活气」（等幅对称会完全相消、打摆子） |
| 击槌 | 短促低通噪声 + 低音区木板闷响 | 有触键质感，但没有尖锐的打击声 |
| 力度 → 音色 | 弹得轻，高频泛音明显更少 | 轻重有别，不是单纯调音量 |
| 延音 | 按音高定长（实测 A2 12.9 s / C4 8.8 s / A5 4.5 s） | 低音厚而长、高音短而清 |

单音验证（`.deepworks/tmp/analyze_piano_note.py`）确认泛音确实是非谐波拉伸的 ——
C4 第 12 泛音：谐波预测 3139.5 Hz、非谐波预测 3208.5 Hz，**实测 3208.5 Hz**；
A2 第 12 泛音：1320.0 / 1357.5 / **1357.5 Hz**。

#### 悠扬向调整（依据试听反馈）

上一版钢琴偏「一颗一颗」，音与音之间还听得见缝。这一版让它连成一条线：
延音整体加长、制音器放缓（像慢慢抬踏板）、音尾互相咬合、残响更宽。

| 手段 | 上一版 | 这一版 |
| --- | --- | --- |
| 基频延音（-60 dB） | 6.8 s（指数 0.62） | **9.5 s（指数 0.55，低音拉得更长）** |
| 旋律 / 伴奏 / 钟声额外延音 | +2.6 / +1.5 / +0.45 s | **+4.5 / +2.4 / +0.85 s** |
| 制音器收尾 | 0.3 s | **最长 1.2 s（余弦松键）** |
| 起音 | 3.0 ms | **4.5 ms（音头更软）** |
| 击槌噪声 / 低音闷响 | 0.085 / 0.045 | **0.052 / 0.022** |
| 力度 → 泛音加成 | 0.34（下限 0.60） | **0.30（下限 0.62，避免糊回低频）** |
| 残响抽头 / 预延迟 | 1.25 s / 28 ms | **2.0 s（左右各 10 抽头）/ 38 ms** |
| 曲尾留白 / 渐弱 | 3.0 s / 2.4 s | **3.5 s / 3.0 s** |

客观指标（自检脚本 `.deepworks/tmp/analyze_bgm.py`）：

| 指标 | 上一版钢琴 | 这一版 |
| --- | --- | --- |
| 时长 | 131.0 s | 131.5 s |
| 峰值 / RMS | -1.01 / -18.79 dBFS | -1.01 / -18.65 dBFS |
| 削波 / 静音段 | 0 / 1（片尾渐弱） | 0 / 1（片尾渐弱） |
| 频谱重心 | 1438 Hz | 1409 Hz |
| 200 ~ 800 Hz（琴身） | 81.2% | 83.9% |
| 800 ~ 2000 Hz | 17.0% | 14.3% |
| 2 ~ 6 kHz | 1.4% | 1.5% |
| 钟声动机（2 Hz 包络） | +9.5 dB | +9.3 dB |

「悠扬」在客观上的证据（`.deepworks/tmp/analyze_legato.py`，50 ms 窗口、
-40 dBFS 门限，统计乐曲主体）：**有声占比 97.5% → 99.3%**，
**静音空洞 11 个（合计 2.8 s）→ 1 个（0.6 s）** —— 音与音之间的缝隙基本消失。

单音延音实测（`.deepworks/tmp/analyze_t60.py`，20 s 缓冲区不受截断影响）：

**想更悠扬或更清亮**，改这几处即可：

- `piano()` 的 `t60`（延音长度，越大越悠扬）与 `bright`（力度 → 亮度曲线）
- `VOICE` 里的 `mel_tail` / `arp_tail` / `ost_tail`（各声部的「踏板量」：
  调大 → 音尾更多地叠进彼此，更连绵）

#### 加入小提琴作为伴奏（本条为合成版记录）

> **现状说明**：正式曲目的小提琴**已换成真实采样**，并且**从第 0 小节就与钢琴同时
> 进入**（本条记录的是早先的合成版：音色由 `violin()` 加性合成、进入点也偏晚）。
> 采样版的配比与进入方式见下一节。

在钢琴之上加了**第四层：小提琴长弓铺底**（`tools/make_bgm.py` 的 `violin()` +
`VIOLIN_LINE`）。钢琴是「一颗一颗」，弦乐要的恰恰相反 —— **一条不断的线**：
每小节一个全音符长弓，把钢琴的留白连起来，悠扬感成倍放大。

| 项目 | 做法 | 想要的效果 |
| --- | --- | --- |
| 音区 | 锁定在 **G3 ~ E4（196~330 Hz）**，整条线在钢琴旋律（A4~A5）下方一个八度 | 填满留白，却绝不遮旋律 |
| 线条 | 级进 / 三度为主，段落收束落回主音 A3；第 11、27 小节各写一个 **8 拍长音**跨过段落交界 | 一条能跟着唱的伴奏线，而不是和声垫 |
| 泛音 | 弓弦的自然泛音列（按 1/k 衰减），**没有**钢琴那种非谐性拉伸 | 能听出是两件不同乐器，不是加了个滤波器 |
| 弓毛位置 | 有意做出 **第 7~8 次泛音凹陷**（弓靠近琴码时的那个高频谷） | 弦乐特有的木质「沙沙」质感 |
| 揉弦 | **5.4 Hz、±10 音分**，起弓后 0.45 s 淡入 | 长音会「唱」起来，不是合成器长音 |
| 起弓 / 换弓 | 起弓 0.16 s；长弓内做 0.55 → 1.00 的换弓起伏 | 音头是被「拉」出来的，且长音会呼吸 |
| 空间 | 与钢琴共用同一套残响（同一条干声总线，居中不偏移） | 两件乐器在同一个厅里，而不是贴上去的 |

单音验证（`.deepworks/tmp/analyze_violin_note.py`）逐条确认：

| 检查项 | 结果 |
| --- | --- |
| 泛音结构 | 第 1~12 泛音与设计公式逐条吻合，**最大偏差仅 0.13 dB** |
| 弓毛凹陷 | 第 7 泛音 **-27.9 dB**（以基频为 0 dB），7~8 次泛音处是一个明显的谷 |
| 揉弦 | 载波旁 **±5.4 Hz** 边带，低于载波 18.2 dB —— 正是 ±10 音分应有的值 |
| 起弓 | 到持续电平约 0.28 s（钢琴 5 ms）—— 一听就是弓弦，不是键盘 |

电平配比（`.deepworks/tmp/analyze_violin_mix.py`：把 `piano()` 临时换成静音后
单独渲染弦乐层量得）：弦乐比**整条混音**低 **7.0 dB**，换算到**钢琴层**是低
**5.7 dB**（两个基准别混用 —— 本文件早期把这里的 7.0 dB 写成「比钢琴层低」，
是笔误，已更正）。在旋律频段（440~880 Hz）低 **8.4 dB** —— 是「伴奏」而不是
「二重奏」；在它自己的音区（196~330 Hz）则高出钢琴 6.9 dB，稳稳占住中低音铺底。

加入弦乐前后的整体指标：

| 指标 | 纯钢琴（悠扬版） | 加入小提琴 |
| --- | --- | --- |
| 峰值 / RMS | -1.01 / -18.65 dBFS | -1.01 / **-18.36 dBFS** |
| 削波 / 静音段 | 0 / 1 | 0 / **0** |
| 频谱重心 | 1409 Hz | 1467 Hz |
| 200 ~ 800 Hz（琴身） | 83.9% | 82.9% |
| 800 ~ 2000 Hz | 14.3% | 15.3% |
| 钟声动机（2 Hz 包络） | +9.3 dB | +8.9 dB |
| 有声占比 / 静音空洞 | 99.3% / 1 个（0.6 s） | **99.8% / 0 个** |

弦乐没有让低频变糊（琴身频段 200~800 Hz 基本没变），新增能量都落在它的泛音区
（800~2000 Hz），钟声动机也依然清楚可辨。

**想调弦乐（或者干脆关掉）**，改这几处即可：

- `VOICE["vio_scale"]`：弦乐总音量，**设 0 就完全回到纯钢琴版**（代码原样保留）
- `VOICE["vio_vel"]`：弦乐在各段的力度（入场 / A / B / A′ / 尾奏五档）
- `VIOLIN_LINE`：每个小节的弦乐音与长弓时值 —— 想让它更活跃就加密音符
- `violin()` 的揉弦（`0.0060` 深度 / `5.4` 频率）、起弓 `0.16`、
  换弓起伏 `0.55 + 0.45·sin(πu)^0.75`、泛音滚降 `exp(-fk/4200)`

```powershell

python tools/make_bgm.py --bpm 60        # 更慢
```

#### 改用真实采样音源（去掉电子感）· 本版正式曲目

用户反馈「电子感太强，希望更贴近真实乐器」。上一版是**用数学公式自己算出来的音色**
（加性合成），这一版换成**真实乐器录音采样**：同一份 MIDI 谱 → 用 **FluidSynth +
SoundFont（MuseScore_General.sf3）** 渲染出真实钢琴 / 小提琴 → 再用自建的卷积残响和
温和倾斜做空间与收尾。生成脚本：`tools/make_bgm_sampled.py`（复用 `make_bgm.py` 里
的写谱、残响与倾斜工具）。

**「电子感」到底来自哪里** —— 单音 A/B（`.deepworks/tmp/analyze_sample_note.py`，
同一个 C4 音，合成音 vs 采样音）：

| 检查项 | 合成音 | 采样音 | 说明 |
| --- | --- | --- | --- |
| 泛音之间的本底 | **-148.4 dB**（数字静音） | **-57.2 dB** | 录音永远带着琴体和房间噪声；泛音之间一片死寂，正是「电子味」的根源 |
| 基频包络（去趋势后的起伏） | 6.8 dB | **13.4 dB** | 真实琴弦有拍音与细微起伏，包络不是一条光滑的指数曲线 |
| 非谐波能量占比 | 0.00 % | **0.03 %** | 真实击弦与琴体共振带来的非谐波成分 |
| 频谱重心走向 | 947 → 626 → 468 → 320 Hz（单调下降） | 768 → 1035 → 903 Hz（有起伏） | 真实琴音的明暗不是单调衰减 |

**整曲层面的前后对比**（`.deepworks/tmp/analyze_realness.py`）：

| 指标 | 合成版（上一版） | 采样版（本版） | 怎么看 |
| --- | --- | --- | --- |
| 峰值 / RMS | -1.01 / -18.36 dBFS | -0.72 / -17.96 dBFS | 响度基本没变 |
| 响度（EBU R128） | -15.5 LUFS | **-15.7 LUFS** | 音量听感一致，不会「换了个曲子就变小声」 |
| 削波 / 静音段 | 0 / 0 | 0 / 0 | 干净 |
| 频谱重心 | 1467 Hz | **1394 Hz** | 更暖，少了合成器的高频亮刺 |
| 200 ~ 800 Hz（琴身） | 82.9 % | **93.4 %** | 木头味更重 |
| 800 ~ 2000 Hz | 15.3 % | 5.4 % | 合成版那些「亮」的能量来自合成泛音 |
| 谱平坦度 200 ~ 6000 Hz | 0.137 | **0.225** | 越高越像「录音」，越低越像「音调」 |
| 泛音之间的谱地面 | -59.6 dB | **-52.0 dB** | 多出来的这 7.6 dB 全是真实乐器的细节 |
| 立体声相关 | 0.904 | **0.556** | 采样自带真实录音的立体声宽度（左右是两个拾音位置，不是同一路复制） |
| 钟声动机（2 Hz 包络） | +8.9 dB | **+10.4 dB** | 动机比上一版更清楚 |

单声道折合只掉 **0.75 dB**（无相位抵消）—— 手机外放不会变虚。

**「小提琴和钢琴同时出现」** 也在这一版一并解决：小提琴从**第 0 小节（第 0 秒）**就与
钢琴同时进入，全程 **30 处换音**、两处以 **8 拍长音**跨过段落交界（第 11、27 小节）。
客观验证（`.deepworks/tmp/analyze_legato.py`）：有声占比 **100.0 %**、**0 个静音空洞**
（上一版 99.8 %）。

**声部配比**（干声、未归一，`.deepworks/tmp/analyze_realness.py`）：

| 声部 | RMS | 相对旋律 | 说明 |
| --- | --- | --- | --- |
| 旋律（钢琴） | -37.0 dBFS | 0 dB | 主线条 |
| 小提琴 | -42.5 dBFS | **-5.5 dB** | 清楚可闻，但在旋律之下 |
| 伴奏（分解和弦） | -47.6 dBFS | -10.6 dB | 织体垫底 |
| 钟声动机 | -52.7 dBFS | -15.7 dB | 远处的钟 |

这里有个容易踩的坑：**真实小提琴是持续音**（峰值因数只有 13.8 dB，钢琴是 21 dB），
同样的 RMS 听起来会响得多。所以配比不是照搬上一版的数字，而是按实测重新定到
「旋律下方 5.5 dB」—— 小提琴听得见，但不会盖住旋律。

**想调采样版**，改这几处即可：

- `VOICES["violin"]["vol"]`（当前 50）/ `VOICES["arp"]["vol"]`（72）：各声部总音量
- `SEC_TABLE`：各声部在 5 个段落（前奏 / A / B / A′ / 尾奏）的力度
- `VIOLIN_LINE_FULL`：小提琴每个小节的音与长弓时值（想让它更活跃就加密音符）
- `--wet 0.34`：残响量；`--vio / --arp / --ost / --mel`：单个声部的整体倍数
- `--knee 0.30`：软限幅起点（越小压得越狠、平均响度越高）；`--no-norm` + `--solo` 用于量配比
- `--bpm` / `--sr` / `--seed` / `--no-vibrato`

```powershell
python tools/make_bgm_sampled.py                # 默认输出 assets/music/bgm.mp3
python tools/make_bgm_sampled.py --solo violin --no-norm --wet 0   # 只渲染小提琴层，用于量配比
python tools/make_bgm_sampled.py --out test.mp3 # 试听版，不覆盖正式曲目
```

**重新生成需要额外下载两样东西**（都免费 / 开源，且**不随站点分发** —— 只把渲染好的
mp3 放进仓库，音源文件本身不进 zip）：

| **FluidSynth 2.6.0**（win10-x64） | 渲染器。解压后用 `--fs` 指定 `fluidsynth.exe` 路径，或放进 PATH |

### 怎么放音乐（换歌只有一步）

把 mp3 文件重命名为 **`bgm.mp3`**，放进 `assets/music/` 目录即可，**不需要改任何代码**：

```
assets/
  music/
    bgm.mp3      ← 把文件放这里
```

`assets/music/README.txt` 里也写了同样的说明，以及格式、体积、版权等注意事项。

### 想改配置

全部集中在 `assets/config.js` 的 `music` 一段：

```js
music: {
  enabled: true,                      // 设 false 可整体关掉背景音乐（按钮和气泡都不出现）
  src: "assets/music/bgm.mp3",        // 音频文件路径（相对 index.html）
  volume: 0.35,                       // 初始音量，0 ~ 1（背景音乐建议不超过 0.5）
  loop: true,                         // 是否循环播放
  title: "点一下，边听边逛",           // 进站引导气泡的标题
  hint: "右下角这个按钮可以随时暂停"    // 进站引导气泡的说明文字
}
```

| 想做的事 | 改哪里 |
| --- | --- |
| 换音乐文件 | 把新文件覆盖为 `assets/music/bgm.mp3`，或改 `music.src` |
| 调音量 | `music.volume`（0 ~ 1） |
| 不循环 | `music.loop: false` |
| 暂时不要背景音乐 | `music.enabled: false` |
| 改引导文案 | `music.title` / `music.hint` |

### 为什么不是「一进站就自动播放」

Chrome / Edge / Safari 都禁止页面在**未经用户交互**时播放有声媒体，强行 `autoplay` 必然被浏览器拦下（控制台报 `NotAllowedError`）。所以这里的设计是：

- 访客点右下角按钮 → 开始播放；
- 播放成功后把开关状态记进 `localStorage`，下次进站自动尝试续播；
- 若仍被浏览器拦下，就再亮一次气泡引导点击。

### 音乐文件没放 / 路径写错会怎样

页面不会崩溃。按钮转为 `missing` 状态，气泡提示「还没找到音乐文件」，控制台打印原因。把文件放对后刷新页面即可恢复。

### 调试命令

在浏览器控制台可用：

```js
__BGM.state()   // 当前状态：idle / playing / missing
__BGM.play()    // 手动播放
```
